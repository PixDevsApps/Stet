### How to record evidence

- Record only what was actually run: date, exact command, machine, library versions, raw numbers and pass/fail against the stated bar.
- State the environment: headless Broadway, live Hyprland session, or container. A Broadway timing is not a Wayland timing.
- Record failures and flaky reruns as they happened. Never mark an unrun check as passed; "not verified" is a valid result.
- Keep logs under `target/` or `.local/` (not committed) and name the path in the entry. Both are disposable: `cargo clean` removes `target/`, and `.local/` may be deleted to free space (as on 2026-09-30), so copy the numbers that matter into the entry or report.

## Strategy

The test pyramid follows the crate boundaries: most logic lives in `stet-domain` and is tested fast and exhaustively; `stet-infrastructure` is tested against real files in temporary directories; the GTK layer is driven through its `ActionId`s.

### Domain tests (`stet-domain`)

**proptest:**

- EOL round-trips, including mixed and CR-only input;
- encode/decode for every supported encoding;
- Extended-mode unescape and the template and pattern translation (Boost to PCRE2, `\K`, and routing patterns that can match empty text to our own matcher);
- line operations: sorting is stable, removing duplicates is idempotent;
- applying `TextEdit`s matches a plain `String` model;
- column math (M6);
- the session serde model is forward-compatible (unknown fields ignored, missing fields defaulted);
- the theme fallbacks (every key resolves).

**insta snapshots:**

- the scheme XML and CSS for all 22 built-in `colors.toml` files;
- session JSON;
- JSON and XML formatter output, which keeps tokens verbatim;
- the search parity table.

### Infrastructure tests (`stet-infrastructure`, with `tempfile`)

- **Safe save:** symlinks kept; mode and owner kept; the hard-link fallback; EACCES; a simulated crash between write and rename leaves the original intact.
- **Backups:** the manifest never points at a missing backup; falling back to `.prev` when the session file is corrupt.
- **Find in Files:** filters and `!` excludes, gitignore on and off, hidden folders, binary files skipped, cancel within 50 ms, the 50k-hit cap.
- **Parsing:** encoding detection over the fixture corpus, and malformed `colors.toml` files.

### UI self-tests (`stet --self-test`, from M1)

`stet --self-test <script>` starts the real app (window and all) with its own application id (`<app-id>.SelfTest`) and a scratch directory for its state, cache, fake Omarchy state and fontconfig directories, runs a `.stet-test` script against it, prints a TAP report on stdout and exits 0 only if every step passed. It refuses to run unless GTK targets Broadway (`tools/headless.sh`) or `STET_SELFTEST_ALLOW_LIVE=1` is set. The PKGBUILD `check()` never runs it. A step that runs longer than 300 s (`STET_SELFTEST_STEP_TIMEOUT`, in seconds) fails as timed out, and the steps after it are reported as not run, so a step waiting for a popover or dialog that never comes can't hang a run.

```sh
cargo build
tools/headless.sh 20 target/debug/stet --self-test tests/selftest/files.stet-test
```

`bash tools/ci.sh --ui` runs the smoke test (the app must log `first-frame` on Broadway) and then every script in `tests/selftest/` except `preview*` and `perf-*`, on display `$STET_CI_DISPLAY` (default 9). Each log goes to `.local/selftest-<name>.log`.

**Script format.** One step per line: a command and its arguments, separated by spaces. Lines starting with `#` and blank lines are ignored. `"double quotes"` group words and expand `\n`, `\r`, `\t`, `\\`, `\"` and `\$`. `$TMP` expands to the run's scratch directory (also the working directory for `open` and `spawn-stet`) and `$DIR` to the script's directory. Unknown commands and wrong argument counts are reported before the app starts. A failed step prints `not ok` with the reason; later steps still run.

What the self-tests cannot show: real key presses (keys reach GTK's accelerators only in a live session; the scripts activate actions by name and emit the find entry's key handler), real clicks (`click-tab` replays what libadwaita does on a click on a tab, and `tab-press` runs Stet's own handling of a press; the live check `tab_double_click` double-clicks with the real pointer), drag-and-drop from Nautilus (the drop handler is called directly), the portal's file chooser (headless runs get GTK's own), Hyprland's full screen, fractional scaling, fcitx5, and anything about the compositor, such as which window it gives the keyboard (`assert-focus` checks the window's own focus widget). Broadway also never reports the full-screen state, so only the full-screen action's wiring is checked. Those items are on the manual acceptance list.

### Headless Broadway runs

Every GTK program an agent runs goes through `tools/headless.sh <display> <cmd...>` with its assigned display number, terminates on its own, and leaves no `gtk4-broadwayd` running ([BUILD.md](BUILD.md#headless-gtk-runs)).

What headless runs can show: the code builds, starts, renders, handles actions and exits cleanly; buffer, search and layout costs inside GTK. What they cannot show: Hyprland behaviour, fractional scaling, fcitx5 and text-input-v3, drag-and-drop from Nautilus, clipboard between apps, window rules and focus. Those belong to spike S4 and the manual acceptance list below.

### Search parity suite (M4)

About 60 Boost-style patterns run against the real GtkSourceSearchContext (count, highlight, Find Next), through our own `pcre2` replace engine, and through Find in Files (`grep-pcre2`), and must give the same results. They include `\R`, lookbehind, `\U$1`, and Extended `\r\n` in a CRLF document ([ADR-005](DECISIONS.md)). Patterns the widget cannot handle (`\K`, empty matches) are routed to our own matcher and tested there ([ADR-005 amendment](DECISIONS.md#adr-005-amendment--our-own-replace-engine-2026-09-30)).

As built (2026-10-01): the table has 122 rows (`infrastructure/src/search/parity.rs`), with expected matches, start offsets, replacements or error offsets written out by hand. The unit test `parity_table` runs every row through our matcher and replace engine and, for the 108 rows that are neither routed, buffer-only nor errors, through the Find in Files matcher. The self-test `parity.stet-test` runs the 114 rows that are not routed through a real `GtkSourceSearchContext`; the M4 run compared 110 of them and found no difference ([evidence](#2026-10-01--m4-search-ci-self-tests-widget-parity-and-performance)). Extended `\r\n` in a CRLF document is the row "Extended \r\n in a CRLF document" (on the LF buffer text) and the app-level `search-crlf.stet-test`.

### Fixtures

- Small encoding and line-ending fixtures (M3) are built, not committed as binary files: in code for the infrastructure tests (`infrastructure/src/encoding/fixtures.rs`) and as hex in `tests/selftest/encodings.stet-test` and (M8) `tests/selftest/rif-fixtures.stet-test`, with the same texts (UTF-8 ± BOM, UTF-16 LE/BE ± BOM with NUL and a surrogate pair, Windows-1252, ISO-8859-15, Shift_JIS, GBK, GB18030, Big5, EUC-KR, ISO-2022-JP, CR-only, CRLF, mixed, NUL, binary). The large inputs of the M3 self-tests come from `write-generated`.
- Generated, large, not committed: `python3 tools/gen-fixtures.py` writes seeded, deterministic files to `target/fixtures/` (`big-1m-lines.txt`, `medium-10mb.rs`, `single-line-10mb.json`, `search-1m.log`); record their actual sizes with each result. `cargo clean` removes them; run the script again before a spike.
